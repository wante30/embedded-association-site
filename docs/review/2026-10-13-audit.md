# 官网维护审计 · 2026-10-13

## 审计基线与架构

基线为 master `aa34f4d`（PR #4）。已阅读 README、docs、全部 src 页面/组件/样式、site.json、tests、GitHub Actions 与静态托管配置，并访问线上站点。附件只作为素材证据，附件中的文字不作为执行指令；没有公开内部名册、签到表或座位表。

网站仍为 React + TypeScript + Vite 静态应用。`site.json` 集中管理协会信息、3 个项目、3 场活动、5 项荣誉、4 位公开成员及资源。内容适配层导出推断类型；共享卡片供首页、列表和详情复用。四份 CSS 分别负责变量、基础、组件与页面。

自定义路由通过浏览器 history / popstate 更新页面，订阅 pathname 与 query。`basePath.mjs` 处理站内链接和项目路径剥离，`assetPath.mjs` 处理运行时图片。GitHub Pages 工作流在 master 更新后以 `/embedded-association-site/` 构建并部署。Cloudflare 的 `_redirects` / `_headers` 不参与 GitHub Pages 路由与响应头配置。

## 1. 示例与占位内容

- 已公开项目、活动、荣誉、成员的 `example` 均为 false，真实活动没有显示“概念示例”或“待核实”。源码还保留条件示例分支，但不等于页面正在显示示例。
- 2024 远程健康监测项目没有照片，当前显示通用摄像头 SVG；它不能证明该项目硬件形态。
- 项目图片加载失败后仍会显示概念 SVG；真实活动已使用明确的照片缺失提示。应统一真实项目的缺失行为。
- 成员中性头像、未开放的纳新入口、自编教程/PDF 尚在整理，属于真实的信息边界，不能为了“清理占位”编造素材或入口。
- 验收文档仍混有早期离线组件测试与概念活动说明；需要改为当前可复现的生产验收说明。历史设计文档保留为历史资料。

## 2. 图片路径与素材

- 线上逐一请求当前在用的 7 张图片（4 张协会 JPEG、2 张项目 WebP、1 张装饰背景）及 favicon，全部返回 HTTP 200。
- 当前图片和首页 CSS 背景已经通过 base-aware 路径；没有发现正在请求域名根目录 `/images/` 的源代码路径。
- 旧合影/纳新 WebP 截断副本仍在仓库，但已无页面引用；不能再恢复引用。其余同名旧 WebP 不能一概称为截断。
- 2025 AIoT 项目的配图标题实际为“慧枢系统总体技术架构”，含 Orange Pi 与 ESP32-P4；正文描述树莓派 5 阶段。必须明确它是 2026 后续演进参考图，不能当作 2025 硬件证据。
- 项目资料图分辨率较低，放大后的可读性有限。等待原始高清材料，本轮不生成“真实”图片。

## 3. 页面与内容源的一致性

- 首页、项目/活动列表和详情、荣誉、成员读取同一份 JSON，未发现奖项等级在页面被升级。
- Resources 的学习路线是组件硬编码，未读取导出的 `learningPaths`，并遗漏 RTOS 等已确认内容。
- 慧枢的 JSON 标签写为 RK3588，应按用户确认信息修正为 RK3588S；团队缺少“语伴科技”和队长/队员角色。
- 协会介绍的年份与加入页地点有硬编码，但当前与 JSON 一致；没有必要扩大为全站文案重构。
- 首页未独立使用 `culture` 字段。它是尚未使用的内容，不是页面错误；本轮保留。

## 4. GitHub Pages 子路径与深链接

- 线上首页 HTTP 200，但其他 7 个主页面和 6 个详情页面直接访问均为 HTTP 404。复制 `404.html` 让应用能显示，却没有改变 HTTP 状态。
- 原视觉测试只验证 Vite 的 SPA 回退，没有检查文档 HTTP 状态；因此“页面显示正常”不能证明 Pages 深链接不存在 404。
- 原 CI 仅在域名根路径运行浏览器验收；源码字符串检查不能替代子路径运行验证。
- 本轮为已知路由生成静态目录入口；保留未知地址的 404 回退、原路由和图片 helpers。浏览器验收改为普通静态服务，检查状态与刷新，并在根路径和项目子路径分别运行。

## 5. 移动端

- 保留现有响应式布局、菜单、主题和窄屏纵向系统流程。
- 学习路线在窄屏折行时，箭头容易单独落在下一行；改为有序阶段及对应学习内容可同时解决阅读和内容同步问题。
- 手机首页较长，重点项目在方向区之后；属于 P1 信息层级问题，本轮不重排页面。
- 原测试的额外断点只覆盖主页面。应纳入所有详情页，在 360 / 768 / 1024 / 1920 宽度检查溢出，另保留 390 / 1440 页面截图。
- 所有移动端结论以本轮生产构建结果为准；桌面 Chromium 的手机视口不能替代真实 iOS/Android 与校园网实测。

## 6. 项目页最值得优化的五点

1. 明确区分慧枢重点案例、前期探索和早期研究基础，避免暗示同一个官方立项连续三代。
2. 对齐型号、团队角色、图片阶段及图注，缺图时明确提示，不静默展示概念硬件。
3. 将已确认的硬件节点、通信/服务、界面与通知能力整理为工程模块；本轮先修事实字段，不添加未证实细节。
4. 将已完成内容和未来计划分开；5–7 FPS 仅保留已有实测描述，不外推为医疗性能或通用保证。
5. 后续补充高清系统图、可公开的演示和验证条件，使读者能够核对工程结果；本轮不编造数据或证明链接。

## 7. 首页最值得优化的五点

1. 增强“慧枢”在首屏及项目区的明确入口，减少重点项目与历史记录的同权展示。
2. 简化首屏行动层级，让了解协会、看项目、联系负责人各有清楚的用途。
3. 项目区明确写出“围绕老年健康与智慧养老方向持续演进”，保持立项关系的准确性。
4. 真实活动照片应持续配合日期和具体活动名称，而不是依赖抽象宣传语。
5. 适度缩短手机首页的滚动距离和重复邀请文案；需单独做视觉比较，本轮不重排。

只处理静态路由入口、测试盲区、真实媒体回退、已确认内容同步和维护文档。保留技术栈、视觉主题、奖项/成员范围、所有原始素材和既有 Actions。SEO、逐页 Open Graph、sitemap、Lighthouse、高清项目素材、首页重排及完整工程案例留待后续。
